# 入驻企业名录 · 实施方案

## 一、先看清楚现在的网站是怎么搭的

看过源码后确认的 4 个事实，直接决定了这个功能只能怎么做：

| 事实 | 影响 |
| --- | --- |
| 前台是 `public/experience/` 里的一套单页应用，`index.html` 只有 6 个空容器（首页、消息、我的、资源、详情、后台），内容全由 `app.js` 渲染 | 新页面必须往这套容器里加，不能另起一套 React 页面 |
| 前台读数据走 `bridge.js`：用公开钥匙直接向 Supabase 读 `public_listings` **视图** | 企业数据也应该做成一个视图，前台只读视图 |
| 后台 `/admin/` 是 Next.js 页面，管理员登录后直接读写 `listings` 表，权限由数据库 RLS 规则控制 | 企业表的增删改照抄这套权限写法 |
| 线上是静态导出到 GitHub Pages，**没有服务器**可以跑接口 | Excel 必须在浏览器里解析；前台不能有"导出接口"，只能前端生成文件 |

另外：项目已经装了 `fflate`（解压库，`lib/ima-zip.ts` 在用）。`.xlsx` 文件本质就是一个 zip 压缩包，用它就能读，**不需要安装新的依赖**。

## 二、数据库：新建 `companies` 表

| 字段 | 类型 | 说明 | 公开？ |

- 开启 RLS，匿名用户**不能**直接读 `companies` 表；
- 管理员按园区分权：园区管理员只能管自己园区的企业，超级管理员/内容管理员管全部（复用 `can_manage_park()`）。

## 三、打码：在数据库视图里做，不在页面里做

**为什么不能在 JS 里打码**：那样真实值仍然被发送到了访客的浏览器，懂技术的人打开开发者工具就能看到，等于没打码。

正确做法：原表存真实值 → 另建公开视图 `public_companies` → 视图里直接输出打码后的值 → 前台只读视图。

| 字段 | 存储值 | 前台看到 |
| --- | --- | --- |
| 法定代表人 | 张三丰 | 张** |
| 手机号 | 13812345678 | 138****5678 |
| 邮箱 | abc@qq.com | a***@qq.com |
| 参保人数 | 37 | 只显示"10-50人"，具体数字不出现 |
| 统一社会信用代码 | 91441900MA5xxxx | 91441900**** |

参保人数虽然不公开具体数字，但视图会给出"人数区间"，这样统计图照样能画，隐私也不泄露。

## 四、后台：新增"企业名录"标签页

在现有后台左侧标签里加一个 `企业名录`：

1. **列表**：表格显示企业名称、园区、行业、状态、人数区间；支持按园区/关键词/状态筛选。
2. **新增 / 编辑**：表单录入，敏感字段带"仅管理员可见"提示。
3. **Excel 批量导入**：
   - 支持 `.xlsx` 和 `.csv`；模板列名固定（见下表）
   - 先预览、再确认。逐行校验：缺企业名称、园区不存在、重复企业（同园区同名）都会标红
   - 重复企业可选"跳过"或"更新"，不静默覆盖
   - 导入完显示"成功 N 条 / 跳过 N 条 / 失败 N 条"
4. **导出**：管理员可导出全部字段（含明文），用于交接备份。

**Excel 模板列名**（第一行必须是这些名字，顺序可变）：

```
企业名称* | 所属园区 | 楼栋 | 房号 | 所属行业 | 经营状态 | 成立日期 | 注册资本(万元) | 参保人数 | 法定代表人 | 联系电话 | 邮箱 | 注册地址 | 经营范围 | 官网 | 标签
```

## 五、前台：嵌在房源详情页

前台**不加独立一级入口**，按你选的"嵌在房源/园区页"：

1. **房源详情页底部**新增一块"该园区入驻企业"：
   - 显示企业名称、行业、状态
   - 默认显示 10 家，点"查看全部"展开
   - 顶部有搜索框，可在本园区内按企业名/行业搜索
2. **"查看全部"进入企业名录视图**（新加一个页面容器）：
   - 列表 + 搜索 + 按行业/状态/人数区间筛选
   - 统计图表（行业分布、经营状态、人数区间、成立年份）
   - "导出 CSV"（只含公开的、已打码的字段）
3. **企业详情**（新加一个页面容器）：
   - 公开字段全部展示，敏感字段显示打码值
   - 底部"咨询该企业/该园区"按钮，复用现有留言功能

图表不引入第三方库：用原生 SVG 画柱状图和环形图（约 150 行），不增加加载体积，也不依赖外部 CDN。
