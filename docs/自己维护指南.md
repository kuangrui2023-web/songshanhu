# 自己维护指南

这份文档写给网站所有者本人。按顺序做，就能把网站变成完全由你掌控的普通项目。

## 2. 本地运行

需要先安装 [Node.js](https://nodejs.org/) 22 或更新版本。

```bash
npm ci
```

把 `.env.example` 复制为 `.env.local`，填入 Supabase 的 URL 和 anon key，然后：

```bash
node --env-file=.env.local scripts/generate-config.mjs
npm run dev
```

- 前台：http://localhost:3000/experience/index.html
- 后台：http://localhost:3000/admin
- 首页：http://localhost:3000/

> 本地开发没有开启“目录首页”，所以前台要带 `index.html`。线上不会这样。

修改代码时开发服务器会自动刷新，不需要重启。

## 4. 建立你自己的 GitHub 仓库并发布

1. 注册或登录你自己的 GitHub 账号。
2. 新建一个**空仓库**（不要勾选 README、.gitignore、License），例如 `songshanhu-site`。
3. 在本目录执行（把地址换成你的仓库地址）：

   ```bash
   git remote add origin https://github.com/<你的账号>/<仓库名>.git
   git push -u origin main
   ```

4. 打开仓库 **Settings → Pages**，把 **Source** 选为 **GitHub Actions**。
5. 打开 **Settings → Secrets and variables → Actions**，新增两个 Repository secret（放在 **Variables** 里也能用）：
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`

   配置缺失时，`Deploy GitHub Pages` 会在「检查 Supabase 配置」这一步直接报错停下，不会发一个把报错甩给访客的空站。

   只填公开的 anon key。**绝对不要**把 service_role key 放进这里或任何前端文件。
6. 打开 **Actions** 标签，等待 `Deploy GitHub Pages` 运行完成。
7. 访问 `https://<你的账号>.github.io/<仓库名>/`，前台在 `/experience/`，后台在 `/admin/`。

以后每次修改代码，只要：

```bash
git add .
git commit -m "说明这次改了什么"
git push
```

GitHub Actions 就会自动重新构建并上线。工作流文件在 `.github/workflows/pages.yml`，站点路径会自动取仓库名。

## 5. 新建你自己的 Supabase

> 这一步需要你注册 Supabase（可用 GitHub 账号登录），免费额度足够当前网站使用。

1. 在 https://supabase.com 新建项目，记下 **Project URL** 和 **anon public key**（Settings → API）。
2. 打开 **SQL Editor**，把 `supabase/bootstrap.sql` 全文粘贴后点 **Run**。这一个文件已按正确顺序合并了建表、公开视图、权限和图片存储桶配置，不需要逐个执行。

   如果报错，把错误信息发给维护者核对，不要反复重跑。

3. 创建管理员账号，二选一：

   - **在网页端创建**：Authentication → Users 新建邮箱和密码，复制用户 UUID，然后在 SQL Editor 执行：

     ```sql
     insert into public.admin_users (user_id, role, park, active)
     values ('粘贴管理员UUID', 'superadmin', null, true);
     ```

   - **用脚本创建**：在 `.env.local` 追加 `SUPABASE_SERVICE_ROLE_KEY`、`ADMIN_EMAIL`、`ADMIN_PASSWORD`，然后执行：

     ```bash
     node --env-file=.env.local scripts/create-admin.mjs
     ```

4. 把新项目的 URL 和 anon key 填进本机 `.env.local`，同时在 GitHub 仓库 Secrets 中更新这两个值。
5. 重新运行 Pages 工作流，或等待下一次推送。

### 可选功能

- **AI 找房**：需要部署 `supabase/functions/ai-search` 并配置 DeepSeek 密钥。
- **高德地图**：需要部署 `supabase/functions/amap-proxy` 并配置高德 Key。
- 不配置这两项时，前台浏览、筛选、详情、留言仍然可用，只是 AI 和地图相关功能不可用。

## 6. 把旧房源和图片迁过来

备份已经用 `scripts/export-public-data.mjs` 导出到 `E:\claude code\songshanhu-backup\`（房源 JSON + 原图）。等新 Supabase 执行完 `bootstrap.sql` 后：

1. 在 `.env.local` 追加新项目的 **service_role** 密钥（只在本地，不提交、不发给任何人）：

   ```text
   SUPABASE_SERVICE_ROLE_KEY=粘贴你的 service_role 或 sb_secret_ 密钥
   ```

   > 注意：必须是 **Secret keys** 里 `sb_secret_` 开头的密钥，或旧式 `service_role` JWT。`sb_publishable_` 开头的是公开密钥，只能读公开数据，不能导入。

2. 先演练一次，不写入任何数据：

   ```bash
   node --env-file=.env.local scripts/import-public-data.mjs --data="E:/claude code/songshanhu-backup/2026-11-12" --dry-run
   ```

3. 确认没有报错后正式导入（会先上传 810 张图片，再写入 234 条房源，需要几分钟）：

   ```bash
   node --env-file=.env.local scripts/import-public-data.mjs --data="E:/claude code/songshanhu-backup/2026-11-12"
   ```

4. 打开前台确认房源和图片正常，再用后台逐条核对园区、联系方式等信息。

**注意：** 旧项目的留言咨询、管理员账号属于私有数据，没有原后台权限无法导出，迁移后需要重新积累。

## 7. 域名

`denglai.xin` 已在阿里云购买并完成实名。两条路：

- **继续 GitHub Pages**：在仓库 Settings → Pages 填自定义域名，并在阿里云 DNS 添加 CNAME 记录；国内访问速度一般，且不需要备案（但微信内打开可能提示非官方链接）。
- **内地服务器**：访问最稳，需要购买主机并完成 ICP 备案；备案完成前不能解析到内地服务器。

## 8. 安全提醒

- `service_role` key 等同于数据库管理员密码，只能保存在本机或服务端，绝不能出现在网页、GitHub、聊天截图中。
- `anon` key 是公开的，可以出现在前端。
- 定期把 `listings.json` 和 `media/` 复制到网盘或移动硬盘。
- 后台密码不要与微信、邮箱等重要账号相同。
