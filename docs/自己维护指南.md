# 自己维护指南

这份文档写给网站所有者本人。按顺序做，就能把网站变成完全由你掌控的普通项目。

## 1. 现在有什么

| 内容 | 位置 |
| --- | --- |
| 完整源码 | 本仓库（推送到你自己的 GitHub 账号后即归你所有） |
| 房源与图片备份 | `E:\claude code\songshanhu-backup\` 下按日期存放 |

## 2. 本地运行

需要先安装 [Node.js](https://nodejs.org/) 22 或更新版本。

```bash
npm ci
```

把 `.env.example` 复制为 `.env.local`，填入 Supabase 的 URL 和 anon key，然后：

```bash
node --env-file=.env.local scripts/generate-config.mjs
npm run dev
```

- 前台：http://localhost:3000/experience/index.html
- 后台：http://localhost:3000/admin
- 首页：http://localhost:3000/

> 本地开发没有开启“目录首页”，所以前台要带 `index.html`。线上不会这样。

修改代码时开发服务器会自动刷新，不需要重启。

## 4. 建立你自己的 GitHub 仓库并发布

1. 注册或登录你自己的 GitHub 账号。
2. 新建一个**空仓库**（不要勾选 README、.gitignore、License），例如 `songshanhu-site`。
3. 在本目录执行（把地址换成你的仓库地址）：

   ```bash
   git remote add origin https://github.com/<你的账号>/<仓库名>.git
   git push -u origin main
   ```

4. 打开仓库 **Settings → Pages**，把 **Source** 选为 **GitHub Actions**。
5. 打开 **Settings → Secrets and variables → Actions**，新增两个 Repository secret（放在 **Variables** 里也能用）：
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`

   配置缺失时，`Deploy GitHub Pages` 会在「检查 Supabase 配置」这一步直接报错停下，不会发一个把报错甩给访客的空站。

   只填公开的 anon key。**绝对不要**把 service_role key 放进这里或任何前端文件。
6. 打开 **Actions** 标签，等待 `Deploy GitHub Pages` 运行完成。
7. 访问 `https://<你的账号>.github.io/<仓库名>/`，前台在 `/experience/`，后台在 `/admin/`。

以后每次修改代码，只要：

```bash
git add .
git commit -m "说明这次改了什么"
git push
```

GitHub Actions 就会自动重新构建并上线。工作流文件在 `.github/workflows/pages.yml`，站点路径会自动取仓库名。

## 5. 新建你自己的 Supabase

> 这一步需要你注册 Supabase（可用 GitHub 账号登录），免费额度足够当前网站使用。

1. 在 https://supabase.com 新建项目，记下 **Project URL** 和 **anon public key**（Settings → API）。
2. 打开 **SQL Editor**，把 `supabase/bootstrap.sql` 全文粘贴后点 **Run**。这一个文件已按正确顺序合并了建表、公开视图、权限和图片存储桶配置，不需要逐个执行。

   如果报错，把错误信息发给维护者核对，不要反复重跑。

   > 已有项目新增“客户账号”功能时，不用重跑 `bootstrap.sql`，只需单独执行 `supabase/customer_accounts.sql`（见第 9 节）。

3. 创建管理员账号，二选一：

   - **在网页端创建**：Authentication → Users 新建邮箱和密码，复制用户 UUID，然后在 SQL Editor 执行：

     ```sql
     insert into public.admin_users (user_id, role, park, active)
     values ('粘贴管理员UUID', 'superadmin', null, true);
     ```

   - **用脚本创建**：在 `.env.local` 追加 `SUPABASE_SERVICE_ROLE_KEY`、`ADMIN_EMAIL`、`ADMIN_PASSWORD`，然后执行：

     ```bash
     node --env-file=.env.local scripts/create-admin.mjs
     ```

4. 把新项目的 URL 和 anon key 填进本机 `.env.local`，同时在 GitHub 仓库 Secrets 中更新这两个值。
5. 重新运行 Pages 工作流，或等待下一次推送。

### 可选功能

- **AI 找房（已接通）**：云函数 `ai-search` 已部署，密钥存在 Supabase → Edge Functions → Secrets 的 `DEEPSEEK_API_KEY`。更换密钥后不需要改代码；本机 `.env.local` 也保留一份，方便重新部署。DeepSeek 按量计费，余额不足时前台会提示「AI 暂时不可用」，去 platform.deepseek.com 充值即可。
- **高德地图**：需要部署 `supabase/functions/amap-proxy` 并配置高德 Key。
- 地图未配置时，前台浏览、筛选、详情、留言和 AI 找房仍然可用，只是地图相关功能不可用。

## 7. 域名

`denglai.xin` 已在阿里云购买并完成实名。两条路：

- **继续 GitHub Pages**：在仓库 Settings → Pages 填自定义域名，并在阿里云 DNS 添加 CNAME 记录；国内访问速度一般，且不需要备案（但微信内打开可能提示非官方链接）。
- **内地服务器**：访问最稳，需要购买主机并完成 ICP 备案；备案完成前不能解析到内地服务器。

## 8. 日常修改：加房源、改价格、改文案

### 8.1 加房源、改价格（不用改代码，推荐）

打开后台 `https://kuangrui2023-web.github.io/songshanhu/admin/`，登录后点左侧「房源管理」。

- **新增房源**：右上「新增房源」→ 先选「写字楼 / 厂房」→ 填标题、园区（输入框会提示已有园区）、面积等 → 在「租赁费用与条款」填租金单价和物业费 → 填联系人和电话 → 上传照片 → 点「发布房源」。
- **发布必填**：标题、园区、面积、招商联系人和电话、至少 1 张真实照片。缺项会提示，资料没齐可以先「保存草稿」。
- **改价格**：在列表里点房源标题进入编辑，改「租金单价」「物业费单价」，再点「保存并发布」。前台几秒内就会更新。
- **下架 / 删除**：列表里直接点「下架」或「删除」；删除会进回收站，可以恢复。
- **一次性加很多套**：用「批量导入」，按模板填 CSV。

> 租金和物业费填的都是**单价**（元/㎡·月），不是每月总价。系统按「单价 × 面积」自动算出月租金、月物业费和每月合计。例如 2291㎡ × 20 元 = 45,820 元/月。

### 8.2 改网站文案

前台页面的大部分文字写在 `public/experience/app.js` 里，用编辑器的「全局搜索」（VS Code 按 `Ctrl+Shift+F`）搜想要改的那句话即可定位。几个常用的：

| 想改的内容 | 位置 |
| --- | --- |
| 首页大标题「找到适合企业的下一处空间」 | `public/experience/app.js:141` |
| 首页小标题「东莞 · 松山湖 / 企业空间与产业资源」 | `public/experience/app.js:140` |
| 首页副标题「写字楼、厂房与研发空间…」 | `public/experience/app.js:142` |
| 首页服务标语「园区直租·免佣看房…」 | `public/experience/app.js:158` |
| 浏览器标签标题、搜索描述 | `public/experience/index.html:11`、`:14` |

改的时候只替换引号里的中文，不要动 `${...}`、`<br>` 这类符号。

**不用改代码就能改的**：后台「平台参数」里可以改平台名称、招商热线、分享标题和分享简介，保存后刷新网站就生效。

改完在本地 `npm run dev` 看一眼，再 `git add . && git commit -m "改了什么" && git push`，等两三分钟线上自动更新。

## 9. 客户账号（注册、登录、找回密码）

### 9.1 客户怎么用

- **电脑端**：右上角「登录」→ 切到「注册」，填邮箱和密码（8 位以上），点「注册并登录」即可，不需要收验证邮件。
- **手机端**：「我的」页面顶部有「登录 / 注册」入口。
- **登录后提交的留言**记在账号名下。换手机或换电脑，用同一邮箱登录，仍能在「我的 → 我的留言」看到留言和回复。
- **未登录提交的留言**仍按原来的方式查看（回执保存在这台设备的浏览器里），不会自动归到某个账号，也不会按手机号认领——这是故意的，避免别人填你的手机号就能看到你的留言。
- **忘记密码**：登录面板点「忘记密码」，填邮箱；收到邮件后点链接，在打开的页面设置新密码。邮件可能进垃圾箱，免费版还有每小时发信数量限制，偶尔延迟属正常。

### 9.2 开通前要做的四件事（Supabase 后台）

客户注册登录只用到 Supabase 自带的账号系统，但下面四项缺一不可：

1. **执行数据库脚本**：SQL Editor → 粘贴并运行 `supabase/customer_accounts.sql`。全新项目直接跑最新的 `bootstrap.sql` 已包含，无需单独执行。
2. **关闭邮箱验证**：Authentication → Sign In / Providers → Email，把 **Confirm email** 关掉。否则注册后要收验证邮件，而我们不打算让客户多这一步。
3. **填网址**：Authentication → URL Configuration
   - **Site URL** 填 `https://kuangrui2023-web.github.io/songshanhu/experience/`
   - **Redirect URLs** 追加 `https://kuangrui2023-web.github.io/songshanhu/experience/reset.html`
   （自己换域名后，这两处要同步换成新网址，否则重置密码的邮件链接会打不开。）
4. **配置发信邮箱（找回密码要用）**：Authentication → Emails → SMTP Settings
   - Host：`smtp.qq.com`；Port：`465`；加密方式选 **SSL**
   - Username：你的 QQ 邮箱地址，例如 `331656408@qq.com`
   - Password：QQ 邮箱的**授权码**，不是 QQ 登录密码。获取方法：QQ 邮箱网页版 → 设置 → 账户 → 开启「SMTP 服务」→ 按提示生成授权码
   - Sender name 填 `松山湖产业招商`，Sender email 填同一个 QQ 邮箱
   - 保存后，到网站点一次「忘记密码」实测能否收到邮件

> 邮件发不出去时，先检查授权码是否过期、端口是否 465+SSL、发件邮箱是否和 Username 一致。

### 9.3 管理员怎么查看客户账号

- **看有哪些客户**：Supabase → Authentication → Users，能看到注册邮箱、注册时间、最后登录时间。
- **看客户留言**：仍在后台「留言管理」里，和未登录客户的留言一起显示；登录客户的留言会带账号邮箱，方便对照。
- **删除某个客户**：在 Authentication → Users 里点该行右侧菜单删除。他提交过的留言会保留（只是不再挂在任何账号下），后台照常能看。
- **权限**：客户账号和管理员账号存在同一张用户表里，但后台权限只看 `admin_users` 表，客户注册一百个也进不了后台。

## 10. 安全提醒

- `service_role` key 等同于数据库管理员密码，只能保存在本机或服务端，绝不能出现在网页、GitHub、聊天截图中。
- `anon` key 是公开的，可以出现在前端。
- 定期把 `listings.json` 和 `media/` 复制到网盘或移动硬盘。
- 后台密码不要与微信、邮箱等重要账号相同。
